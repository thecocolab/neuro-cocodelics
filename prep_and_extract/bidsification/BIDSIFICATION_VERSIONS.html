cocodelics — Bidsification Versions & Differences

MEG raw (CTF .ds / FieldTrip .mat) → BIDS .fif. Generated 2026-07-08 from a scan of both repos.

Yes — there are three parallel implementations of bidsification. Two are standalone per-dataset script sets (one legacy, one active); the third is injected into the coco-pipe pipeline. They share the same core logic but diverge on paths, robustness, dataset coverage, and one leftover debugging bug.

3. V1 → V2 (standalone evolution)

Same skeleton per dataset (load .mat/.ds → inspect metadata → build BIDS entities → write_raw_bids). V2 changed:

Paths (repointed 2026-07-08 to the shared, durable project storage)

  • Raw source: V1 ~/scratch/data/MEG_* (now empty) → V2 /project/def-kjerbi/data/MEG_*/meg_data (shared raw).
  • BIDS output: V1 ~/scratch/…/meg_data_BIDS → V2 /project/rrg-kjerbi/shared/neuro-cocodelics/MEG_<D> (backed-up, group-writable).
  • Metadata (csv/pkl/txt): V1 wrote next to the dataset → V2 uses a dedicated OUTPUT_PATH with os.makedirs(...) (V1 could crash if the dir was missing).
  • LSD: V1 hardcoded absolute 352.html / meg_bids.csv paths → V2 uses os.path.dirname(__file__) (portable, self-contained).

Robustness / correctness

  • Idempotency: V2 wraps writes in if not os.path.isfile(bids_path.fpath): … else skip. V1 always re-wrote (and always overwrite=True).
  • Explicit BIDS entities: V2 uses BIDSPath(…, datatype='meg', suffix='meg', extension='.fif'); V1 relied on defaults.
  • Psilocybin crop (scientific!): V2 crops each recording to the post-infusion rest window (InfusionStop → RestStop). V1 wrote the whole recording uncropped.

5. Known issues & gotchas

⚠ breakpoint() at redefinitions_cocosprint.py:835 is uncommented. Inside fieldtrip_to_bids() — it hangs any non-interactive (pipeline / sbatch) run. Eight other breakpoint() calls in the file are commented out; this one is not. Remove before running V3 through the pipeline.
⚠ r2c (V3) cannot bidsify ketamine or tiagabine. Only the standalone scripts (V1/V2) handle them. If a fresh rebuild goes through the pipeline, those two datasets will be skipped.
  • LSD is a 3-step flow: 1download.py (fetch .ds from Dropbox) → 2bidsifying_preparation.py (parse + apply the Jordan-Venkatesh corrections → meg_bids.csv) → 3bidsifying.py (write BIDS). The other datasets are a single 1bidsifying.py.
  • Jordan-Venkatesh corrections (LSD): fix misnamed subject IDs (e.g. 231109-1→230911-1), task typos (Opoen1→Open1, Audio→Music), drop spurious extra recordings (Music2/Video2/Closed12), and assign placebo-vs-LSD session per subject by date. Target = 20 subjects × 6 tasks × 2 sessions.
  • The 413 raw LSD .ds include MMN and other non-study tasks; the correction logic filters to the 6 study tasks (Closed1/2, Open1/2, Music, Video).

6. Recommendation

  • Treat V2 (neuro-cocodelics/prep_and_extract/bidsification/) as the source of truth — per-dataset, reproducible, sourced from shared /project, idempotent, full 5-dataset coverage.
  • Treat V1 as history; consider archiving the old cocodelics repo.
  • Before ever running V3 in the pipeline: remove the breakpoint() and port ketamine/tiagabine — or keep bidsification as the standalone V2 stage and let the pipeline consume its BIDS output.
  • Still pending on V2 (see prep_and_extract/TODO.md §3): a cluster test-run, verifying the LSD corrections against the /project tree, and minor cleanup (dead docstring, main() guard).
